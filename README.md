# Black Cloud — Game Development & Cybersecurity Studio

Black Cloud is an independent development studio and cybersecurity research laboratory established in **2021**.

This repository contains the full-stack web platform for Black Cloud, providing an open public visitor showcase for games, technical tooling, and CTF research alongside a secure, private administration portal for the studio team.

---

## Architecture & Security Principles

1. **Zero Public Authentication**: Visitors browse freely without accounts. There are NO registration forms, sign-in buttons, public user profiles, or visitor login pages anywhere on the public website.
2. **Private Team Administration**: Authorized studio administrators access the management portal through a single dedicated route:
   ```
   https://<domain>/admin/login
   ```
3. **Three Game Publication Modes**:
   - **Download Only**: Visitors can download the released game build.
   - **Test Only**: Visitors can access playtesting guidelines and alpha testing builds; release builds are strictly inaccessible.
   - **Download + Test**: Both release downloads and playtest actions are available simultaneously.
4. **Tools Catalog Discretion**: The `/tools` showcase is an architectural and informational catalog only. Public binary downloads and executable uploads are strictly disabled by policy.
5. **Secure Storage & Time-Limited Download Tokens**: Direct storage paths are never exposed to clients. Game build downloads are served via signed, 15-minute time-limited tokens generated by `/api/games/:slug/download-url`.
6. **Robust Team Authentication**:
   - Initial administrator identity: `DevAdam`
   - Initial administrator password: configured via deployment secret `ADMIN_PASSWORD`
   - Server-side sessions with HttpOnly, SameSite cookies and IP-based rate limiting (5 failed attempts locks for 15 minutes).

## Getting Started

### 1. Prerequisites
- Node.js 18+ (tested on Node 20 / 22)
- npm or yarn

### 2. Installation
```bash
npm install
```

### 3. Environment Configuration
Create a `.env` file based on `.env.example`:
```bash
cp .env.example .env
```

Set the following variables:
```env
# Team administrator password for DevAdam (Required for production)
ADMIN_PASSWORD="YourStrongStudioPassword2026!"

# Optional cryptographic secret for signing sessions
SESSION_SECRET="your-cryptographic-random-session-secret"

# Host port (default: 3000)
PORT=3000
```

### 4. Running the Development Server
```bash
npm run dev
```
The full-stack Express server will start on `http://0.0.0.0:3000/`.
- Public Site: `http://localhost:3000/`
- Team Portal: `http://localhost:3000/admin/login`

## Production Deployment

### 1. Building the Frontend
```bash
npm run build
```
This compiles the React + Tailwind application into the `dist/` directory.

### 2. Starting the Production Server
```bash
npm start
```
This runs `node server.ts`, serving both the backend API endpoints and the static production bundle.

### 3. Docker Deployment
```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
RUN npm run build
EXPOSE 3000
ENV NODE_ENV=production
CMD ["node", "server.ts"]
```

## Studio Management Guide

### Managing Games & Builds
1. Navigate to `http://<domain>/admin/login` and authenticate as `DevAdam`.
2. Go to **Games & Builds** (`/admin/games`).
3. Click **Add New Game** or click the edit icon on an existing title.
4. Select the **Availability Mode**:
   - `Download Only`: Displays the Download button.
   - `Test Only`: Displays the Join Playtest button and modal.
   - `Download + Test`: Displays both options.
5. In the **Private Binary Storage Packages** section:
   - Upload your release archive (`.zip`, `.tar.gz`, `.exe`, `.dmg`).
   - Upload your separate playtest archive if active.
6. Click **Save Game Record**.

### Publishing News & Devlogs
1. Navigate to `/admin/news`.
2. Click **Create Article**.
3. Fill in the title, excerpt, markdown content, category, author label, and featured image.
4. Set status to **Published** for public visibility or **Draft** for private review.
5. Click **Save Article**.

### Cybersecurity Tools Catalog
1. Navigate to `/admin/tools`.
2. Click **Add Tool Entry**.
3. Specify title, short summary, full architectural breakdown, tech stack tags, and status (`Active`, `Beta`, `Research`).
4. Link to official documentation or external GitHub repositories.
5. Note: As per studio policy, no public downloads are enabled for security tools.

### CTF Results & Write-Ups
1. Navigate to `/admin/ctf`.
2. Click **Record CTF Result**.
3. Enter competition name, verified placement (e.g. `Top 4%`), score, solved challenge roster with point values, and technical walkthrough.
4. Ensure all write-ups adhere to responsible disclosure principles.

## Troubleshooting & Verification

| Issue | Cause | Resolution |
|---|---|---|
| Admin login fails | Incorrect password or username mismatch | Verify username is `DevAdam` and password matches `ADMIN_PASSWORD` in `.env` |
| "Too Many Requests" lockout | Exceeded 5 failed attempts | Wait 15 minutes for the rate limiter window to expire, or restart the server |
| Download link expired | Download tokens expire after 15 minutes | Click the download button again to generate a fresh token |
| "Release build unavailable" | Availability mode is `Test Only` or build is unattached | Set availability mode to `download` or upload a release archive in `/admin/games` |
